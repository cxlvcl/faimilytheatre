## Цвет логотипа в контактах при обновлении

Причина переключения цветов: reveal-анимация задавала логотипу inline `filter: blur(...)`, перекрывая CSS `invert(1)`, а после завершения очищала inline-фильтр и возвращала инверсию. Reveal перенесён на отдельную обёртку по ширине логотипа; цветовой фильтр остаётся на самом изображении и больше не участвует в анимации. Размер, пропорции и отступы сохранены. Сборка, ESLint и 13 проверок CSS/SVG/локального HTTP прошли; браузер не открывался, публикации не было.

## SEO по приложенному заданию

Существующие маршруты сохранены: `/`, `/repertoire`, `/repertoire/:slug`, `/afisha`, `/faq`, `/franchise`. Разделы «О театре» и «Контакты» остаются якорями главной, а не дублирующими страницами. Отдельные URL событий не выдумываются — их нет в текущей модели.

### Метаданные и индексируемый HTML

Единый источник метаданных — `api/src/Core/Seo.php`: title, description, canonical, Open Graph, Twitter, robots и JSON-LD. Для спектаклей используются существующие title/short_description/изображения. Домен берётся из `base_url`, не зашит в клиенте. Невалидные или чрезмерно длинные краткие описания получают понятный fallback с названием спектакля.

`api/seo/index.php` возвращает видимый HTML с реальными заголовками, описаниями, ссылками и данными базы до JavaScript. Динамические страницы выводит `PageHtml.php`; HTML главной и франшизы собирается из React-компонентов при сборке. Это не отдельный скрытый SEO-текст. На хостинге Node для рендеринга не нужен.

`PageSeo.tsx` обновляет метаданные при SPA-переходах через `/api/public/seo`; старые canonical/JSON-LD не остаются на новом URL. На каждой странице один H1, названия спектаклей в списках — H2 и обычные индексируемые ссылки. Добавлены видимые хлебные крошки, ссылки из афиши на спектакли и ближайшие показы на страницах спектаклей.

### Структурированные данные

- `TheaterGroup`: название, сайт, изображения, реальные контакты и город.
- `BreadcrumbList`: соответствует иерархии страниц.
- `TheaterEvent`: реальные названия, даты, известное время начала, площадки и связь со спектаклем. Для неизвестного времени не подставляется полночь.
- Цена, статус события, полный адрес площадки и состав исполнителей не выдуманы: отдельных достоверных полей в текущей модели нет. Расширенный результат Google не гарантирован; для него могут потребоваться дополнительные реальные данные и отдельные страницы событий в будущем.

### Canonical, robots, sitemap, 404

- Canonical без tracking/query-параметров. Нормализация регистра и завершающего слеша — 301 для существующих страниц.
- В production предусмотрен 301 на HTTPS и основной hostname из `base_url`. При прокси необходимо указать только подтверждённые IP в `seo.trusted_proxies`; заголовок `X-Forwarded-Proto` от произвольных клиентов не считается доверенным.
- Старые slug не менялись. Для действительно изменённых адресов предусмотрен явный словарь `seo.redirects`; массовых редиректов неизвестных адресов на главную нет.
- Неизвестные страницы/спектакли возвращают настоящий HTTP 404 и `noindex`, без canonical на главную.
- Sitemap генерируется из существующих маршрутов и текущих спектаклей; у спектаклей `lastmod` из `updated_at`. Админка/API/технические URL не включаются.
- В robots закрыты технические разделы; локальная тестовая среда дополнительно полностью закрыта от индексации. Robots не заменяет серверную авторизацию.
- Для Яндекс Вебмастера и Search Console предусмотрены реальные verification-значения через `seo.yandex_verification`, `seo.google_verification` либо переменные `THEATRE_YANDEX_VERIFICATION`/`THEATRE_GOOGLE_VERIFICATION`. Фиктивные коды не добавлялись.

Подход к видимому серверному HTML соответствует [рекомендациям Google по JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics). Тип события выбран по [Schema.org TheaterEvent](https://schema.org/TheaterEvent); ограничение срабатывания reveal у нижней границы страницы использует документированный `clamp()` в [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/).
