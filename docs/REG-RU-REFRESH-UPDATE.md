# Обновление сайта: фотографии, надписи, анимации и SEO

Для уже работающего сайта `театрмузыкиипеска.рф` на server281.hosting.reg.ru.
Это не повторная установка: **базу не импортировать, config.php не заменять,
uploads не трогать, пароли и DNS не менять**. Админку пересобирать не нужно.

Три архива относятся к одной сборке и устанавливаются строго по порядку.
Старые архивы от 23–24 сентября для этого обновления не подходят.

## 1. Резервная копия до распаковки

В ispmanager сохраните копию текущих файлов **вне публичного каталога сайта**:

- `~/www/private/api/`, `~/www/private/manifest.json` и `~/www/private/ssr/`, если она уже существует;
- `~/www/xn--80aanbjgaodo1bgudcs1l.xn--p1ai/media/` и `fonts/`.

Можно скачать их на Mac или сделать архив в `~/www/private/backups/`.
Файлы в `assets/` не удалять: они нужны открытым вкладкам и для отката.
Этот пакет не меняет базу и пользовательские uploads. Не запускайте миграции/seed.

## 2. Публичные файлы — первый архив

Откройте:

`~/www/xn--80aanbjgaodo1bgudcs1l.xn--p1ai/`

Загрузите **01-public-update.zip** и распакуйте **в текущую папку**, с заменой
совпадающих файлов. В архиве только `assets/`, `fonts/`, `media/`.
Папки объединяются с существующими: удалять их целиком нельзя.
Лишнюю вложенность `public-update/` создавать не нужно.

На этом шаге текущая версия сайта ещё работает со старым манифестом.

## 3. Серверные зависимости — второй архив

Откройте соседнюю приватную папку:

`~/www/private/`

Загрузите **02-private-update.zip** и распакуйте **сюда**, разрешив замену
совпадающих файлов. Он обновляет PHP API и добавляет `ssr/home.html` и
`ssr/franchise.html`. Это статическая разметка; спектакли и афиша берутся из
существующей серверной базы. Рабочего `config.php` в архиве нет.

Проверьте наличие `api/src/Core/Seo.php`, `api/src/Core/PageHtml.php`,
`ssr/home.html`, `ssr/franchise.html`. Не переходите к шагу 4 при ошибке распаковки.

## 4. Включение обновления — третий архив

Оставаясь в **`~/www/private/`**, загрузите **03-activate-update.zip** и
распакуйте с заменой. Он содержит `manifest.json` и `api/seo/`.
Именно этот шаг включает новую сборку и серверную SEO-разметку.
Внутри `private/` не должно появиться второй папки `private/`.

Все три архива должны быть из одной папки `REG-RU-REFRESH-…`.
Ничего из приватных архивов нельзя распаковывать в публичный корень домена.
После успешной установки удалите с сервера только три загруженных ZIP-архива;
локальные копии сохранены. Особенно не оставляйте публичный ZIP в корне сайта.

## 5. Проверка после включения

Напишите «загрузил все три»: можно проверить сайт запросами HTTP, без браузера.
Проверяются HTTPS/редиректы, главная, афиша, репертуар, страницы спектаклей,
FAQ, франшиза, новый `/api/public/seo`, новые фото и SVG, robots и sitemap.
На основном домене не должно быть общего `Disallow: /` и `noindex` у существующих страниц.
Визуальную проверку desktop/mobile пользователь выполняет сам.

Если возникла ошибка, не меняйте пароль и не импортируйте базу повторно.

## Откат

Верните из резервной копии прежние `private/api/`, `private/manifest.json`
и прежние версии `media/`, `fonts/`; прежнюю `private/ssr/`, если она была.
Новые хешированные assets можно оставить: старый манифест их не использует.
Одного старого manifest для отката **недостаточно**, поскольку обновляется PHP.
База, uploads и рабочий config.php при установке и откате не меняются.

## Повторная сборка на Mac

```sh
export PATH="$PWD/.local-tools/node-v22.23.2-darwin-x64/bin:$PATH"
npm run build -w web
node scripts/package-refresh-update.mjs
```

Скрипт использует штатный `scripts/package.mjs`, проверяет ресурсы манифеста,
упаковывает только необходимые фото, проверяет ZIP и формирует `SHA256SUMS.txt`.
Исходные фотографии, неиспользуемые видео и секреты в архивы обновления не входят.
