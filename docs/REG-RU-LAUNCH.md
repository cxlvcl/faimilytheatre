# Запуск Театра Музыки и Песка на REG.RU

**Для вашей панели ispmanager используйте [пошаговую методичку REG-RU-ISPMANAGER.md](REG-RU-ISPMANAGER.md).** Она содержит конкретный домен, готовые архивы от 23.09.2026, перенос заполненной базы и порядок перехода с Tilda. Этот документ ниже оставлен как общая техническая справка.

Инструкция для текущего проекта. Сайт пока работает локально; создание этого документа ничего на REG.RU не публикует.

## 1. Что потребуется

- Домен и Linux-хостинг с PHP и MySQL, а не тариф только для статических страниц.
- PHP 8.2 или новее: код использует readonly-классы/свойства и современные типы. Расширения: PDO MySQL, mbstring, fileinfo, GD с WebP или Imagick с WebP, zlib, ZipArchive. Желательно EXIF для ориентации фотографий.
- MySQL 8 и кодировка utf8mb4. Локально проект проверялся на MySQL 8.4; другую СУБД/версию нужно проверить отдельно.
- Apache-совместимые правила .htaccess, rewrite, возможность ежедневного cron.
- HTTPS-сертификат, доступ к файловому менеджеру/SFTP и phpMyAdmin. SSH удобен, но импорт можно сделать через панель.

Node.js на сервере не нужен: сборка выполняется на Mac. Приложение админки тоже остаётся на Mac и обращается к серверному API.

Не присылайте пароли от REG.RU, Mac и базы в переписку. Вводите их в панели хостинга или локальной конфигурации.

## 2. Сохранить заполненный контент перед переносом

На время финального экспорта прекратите редактирование в админке. Иначе записи и фотографии могут попасть в разные версии резервной копии.

Откройте терминал в папке проекта:

```sh
cd /Users/artemalekseev/Desktop/theatrpesok
.local-tools/frankenphp php-cli scripts/export-content.php
```

Локальный MySQL должен быть запущен. Если он выключен, сначала выполните в отдельном терминале `zsh scripts/start-preview.sh` и оставьте его работающим.

В новой подпапке `private/backups/export-ДАТА-ВРЕМЯ/` появятся SQL-архив и ZIP с базой и изображениями. Команда напечатает точный путь. Сохраните оба файла отдельно от проекта. Экспорт не очищает контент. Резервные копии конфиденциальны: база содержит учётную запись, заявки и сессии. Не кладите их в публичную папку сайта.

Афиша, репертуар, FAQ и заявки находятся в базе. Загруженные обложки/постеры — в `uploads/`. Для полного переноса нужны **и база, и uploads**, а не только сборка сайта.

## 3. Собрать файлы сайта

```sh
cd /Users/artemalekseev/Desktop/theatrpesok
export PATH="$PWD/.local-tools/node-v22.23.2-darwin-x64/bin:$PATH"
npm run build -w web
npm run package:hosting
```

Последняя команда напечатает путь `release/ДАТА-ВРЕМЯ/`. Внутри:

```text
папка-размещения/
├── public_html/       ← только эта папка доступна через домен
│   ├── index.php
│   ├── .htaccess
│   ├── api/
│   ├── assets/
│   ├── fonts/
│   ├── media/
│   └── uploads/
└── private/           ← вне корня сайта
    ├── api/
    ├── database/
    ├── cron/
    ├── manifest.json
    └── config.example.php
```

Важно: пакет намеренно **не включает** вашу базу, конфиденциальную конфигурацию и пользовательские изображения. Их переносят отдельно.

## 4. Подготовить домен, PHP и HTTPS

В личном кабинете REG.RU откройте услугу хостинга и её панель управления. Названия пунктов зависят от панели.

1. Добавьте домен и привяжите его к хостингу, используя DNS-настройки из вашей услуги. Не меняйте записи почты, если почта уже работает.
2. Выберите PHP 8.2+ и нужные расширения.
3. Установите лимиты: `upload_max_filesize = 16M`, `post_max_size = 40M`, `memory_limit = 256M` или выше. Форма спектакля отправляет две фотографии; приложение ограничивает каждую 15 МБ.
4. Выпустите SSL-сертификат и проверьте HTTPS без предупреждения браузера. После этого включите перенаправление HTTP → HTTPS средствами панели.
5. Определите фактический корень домена. На REG.RU он не обязательно называется `public_html`.

Если на домене уже есть сайт, сначала сделайте его резервную копию и используйте тестовый поддомен. Не загружайте новый пакет поверх чужого/действующего сайта без плана отката.

## 5. Загрузить файлы

Разместите содержимое `public_html/` в корне домена. Папка `private/` должна лежать рядом с этим корнем, на уровень выше публичных файлов, а не внутри него.

Например, если корень домена `/var/www/USER/data/www/example.ru`, приватная папка по текущим загрузчикам должна быть `/var/www/USER/data/www/private`. Если рядом несколько сайтов, заранее выделите отдельную структуру для театра или настройте точные абсолютные пути в загрузчиках; не смешивайте их конфигурации.

Включите отображение скрытых файлов и обязательно перенесите `.htaccess`, в том числе из `uploads/` и `api/`.

Перенесите содержимое локальной `uploads/` в серверную `uploads/`, сохранив имена и вложенность. Можно использовать архив из резервной копии: перед распаковкой посмотрите структуру, чтобы не получить `uploads/uploads/`.

Не загружайте `node_modules`, `.local-tools`, исходники админки, локальный `private/config.php`, `local-access.txt`, SQL-дампы в публичный каталог.

## 6. Создать базу и импортировать данные

1. Создайте **новую пустую базу** и отдельного пользователя базы в панели хостинга. Запишите имя базы, пользователя, пароль и адрес сервера MySQL.
2. Откройте phpMyAdmin и выберите именно новую базу.
3. Через «Импорт» загрузите SQL `.sql.gz` из пункта 2. Если панель не принимает gzip или файл превышает лимит, используйте распакованный SQL либо импорт по SSH с помощью поддержки REG.RU.
4. Дамп содержит `DROP TABLE`: **нельзя импортировать его в чужую или уже рабочую базу** без отдельного согласованного восстановления.
5. После импорта выполните в этой новой базе:

```sql
DELETE FROM admin_tokens;
SELECT COUNT(*) FROM performances;
SELECT COUNT(*) FROM events;
SELECT COUNT(*) FROM faq;
SELECT COUNT(*) FROM franchise_applications;
```

Удаление `admin_tokens` аннулирует перенесённые локальные сессии, но не меняет логин, пароль, спектакли и события. Сравните количества записей с локальной админкой. Не запускайте `database/seed.php` после импорта: заполненная база уже содержит необходимые данные.

## 7. Настроить private/config.php

На сервере сделайте копию `private/config.example.php` с именем `private/config.php`. Измените:

- `base_url` — ваш реальный адрес с HTTPS, без завершающего `/`.
- `db.dsn` — host и имя созданной базы (не локальная `theatre_local`).
- `db.user` и `db.password` — данные пользователя базы.
- `secrets.app` и `secrets.visitor_hash` — два разных случайных значения по 64 hex-символа. На доверенном компьютере можно дважды выполнить `openssl rand -hex 32` и вставить результаты в конфигурацию. Не публикуйте их.
- `uploads.directory` — **абсолютный фактический путь** к публичной папке uploads. Примерный `public_html` из шаблона замените, если корень домена называется иначе.

Остальные пути шаблона указывают внутрь private/. Создайте `private/logs`, `private/runtime`, `private/backups`; процесс PHP должен иметь право записи туда и в `uploads`. Обычно для private/config.php подходят права 600/640, для приватных каталогов 700/750, но владелец и группа зависят от хостинга. Не ставьте 777.

Не заменяйте список разрешённых origins на `*`: в шаблоне уже предусмотрены адреса Tauri. Оставьте `environment = production`.

**До публичного запуска замените слабый локальный пароль админки.** Для этого нужен отдельный безопасный сброс пароля в серверной базе с `password_hash`; не храните новый пароль открытым текстом и не редактируйте hash вручную произвольной строкой. Можно подготовить одноразовый CLI-сброс при настройке конкретного сервера.

После настройки конфигурации обновите схему импортированной базы через CLI PHP:

```text
/ABSOLUTE/PATH/TO/php /ABSOLUTE/PATH/TO/private/database/migrate.php
```

Команда безопасна для повторного запуска: добавляет поле времени начала спектакля, не удаляет записи и не меняет пароль. Если SSH недоступен, проверьте в phpMyAdmin наличие `events.event_time`. Только если поля нет, выполните SQL из `private/database/migrations/002_event_time.sql` в выбранной базе. У старых событий время останется пустым: заполните его в админке в разделе «Афиша → Изменить → Время начала». Время показывается как местное время площадки без пересчёта по часовому поясу посетителя.

## 8. Проверить сайт до анонса

- Главная, меню, `/repertoire`, `/afisha`, `/faq`, `/franchise` открываются по HTTPS.
- `/api/public/performances`, `/api/public/events`, `/api/public/faq` возвращают JSON с вашими данными.
- Фото загружаются; карточка спектакля открывается по её slug.
- Несуществующий адрес возвращает HTTP 404.
- `robots.txt` и `sitemap.xml` содержат настоящий домен.
- Видео работает на компьютере и телефоне; запрос диапазона MP4 возвращает 206. Для браузеров без HEVC есть 4K H.264-версия. Видео большого размера, поэтому проверьте скорость и лимиты трафика.
- `/private/config.php`, `/config.php`, дампы и резервные копии не доступны извне. Проверьте также, что соседняя private-папка не опубликована другим доменом.
- На телефоне текст и кнопки не перекрываются. Создайте только согласованную тестовую заявку и проверьте её в админке.

## 9. Подключить админку к серверу

Текущая сборка смотрит на `127.0.0.1:8080`, то есть на ваш Mac. Для реального сайта пересоберите её с настоящим доменом:

```sh
cd /Users/artemalekseev/Desktop/theatrpesok
export PATH="$PWD/.local-tools/cargo/bin:$PWD/.local-tools/node-v22.23.2-darwin-x64/bin:$PATH"
export RUSTUP_HOME="$PWD/.local-tools/rustup"
export CARGO_HOME="$PWD/.local-tools/cargo"
VITE_API_BASE=https://YOUR-DOMAIN.ru/api npm run tauri -w admin -- build --bundles app
```

Замените `YOUR-DOMAIN.ru` перед запуском. Откройте новую `admin/src-tauri/target/release/bundle/macos/Theatre Admin.app`, предварительно закрыв старую через ⌘Q. Проверьте, что видны импортированные записи и изменение в админке появляется на серверном сайте.

В текущей неподписанной сборке сохранение входа между запусками отключено: токен только в памяти, Связка ключей не используется. После закрытия приложения нужно войти снова. Это осознанное временное отличие от исходного ТЗ; постоянную сессию следует возвращать вместе со стабильной цифровой подписью приложения. Не отключайте защиту macOS и не разрешайте всем приложениям доступ к старому элементу Связки ключей.

## 10. Ежедневные резервные копии

В планировщике хостинга настройте ежедневный запуск **CLI PHP той же версии 8.2+**:

```text
/ABSOLUTE/PATH/TO/php /ABSOLUTE/PATH/TO/private/cron/daily.php
```

Пути необходимо взять из вашей услуги REG.RU: не вставляйте пример как готовую команду. Cron выполняет очистку старой аналитики и сохраняет 7 дневных копий базы и 4 недельных ZIP-копии базы вместе с изображениями. Убедитесь, что хватает диска; периодически скачивайте резервную копию отдельно от хостинга.

Запустите команду вручную один раз, проверьте сообщение об успехе и появление `.sql.gz` в private/backups; ZIP создаётся по воскресеньям. При ошибке смотрите private/logs, не включайте показ ошибок посетителям.

## Если что-то не работает

- **500:** смотрите серверный журнал; проверьте PHP, расширения, config.php, доступ к MySQL и разрешения каталогов.
- **Пустые списки:** проверьте, что импортировали нужную базу, а config.php указывает именно на неё.
- **Нет фото:** проверьте перенос uploads, абсолютный uploads.directory и права чтения.
- **Админка не соединяется:** проверьте VITE_API_BASE, HTTPS, доступность API и allowed origins. Перезапустите правильную сборку.
- **Запрос Связки ключей от старого процесса:** нажмите «Отказать», завершите старую админку и откройте новую. Новая версия не вызывает операции Keychain; не вводите пароль Mac в поля сайта.

## Откат

До запуска сохраните предыдущие файлы и базу. При неудачном переносе верните файлы и согласованную резервную копию базы **одной даты**, затем восстановите соответствующие uploads. После восстановления аннулируйте admin_tokens. Не импортируйте старый дамп поверх новых заявок без учёта их сохранения.
