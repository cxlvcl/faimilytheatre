## 3. Создать сайт в ispmanager

**Где: ispmanager, открытый на скриншоте.**

1. Слева нажмите **«Сайты» → «Создать сайт»**. Если такой домен уже есть в списке, откройте его настройки, не создавайте дубликат.
2. Выберите обычный сайт без установки CMS.
3. Домен: `театрмузыкиипеска.рф`.
4. Если кириллица не принимается, используйте его техническую запись: `xn--80aanbjgaodo1bgudcs1l.xn--p1ai`. Это тот же домен.
5. При необходимости добавьте псевдоним `www.театрмузыкиипеска.рф`. Если используете его, позже для него также нужны DNS и сертификат.
6. Включите PHP. Для этой сборки нужен Apache-совместимый режим с `.htaccess`, например **FastCGI (Apache)**, а не только Nginx без обработки правил Apache.
7. На этом этапе не включайте принудительный HTTPS, если действующего сертификата на новом хостинге ещё нет.
8. Сохраните сайт. Запишите показанные **IP сайта** и **корневую директорию**.

Создание сайта в панели и смена DNS у регистратора — разные действия. Пока выполняем только первое. Названия отдельных кнопок могут немного различаться. [Добавление домена](https://help.reg.ru/support/hosting/privyazka-domena-k-hostingu/kak-privyazat-domen-k-hostingu), [режим PHP](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/kak-smenit-versiyu-php-na-hostinge).

В дальнейшем слова `ВАШ_ЛОГИН`, `ПАПКА_САЙТА`, `ИМЯ_БАЗЫ` и `IP_ХОСТИНГА` — обозначения, которые нужно заменить своими значениями. Не вставляйте их буквально.

## 4. Настроить PHP и проверить MySQL

**Где: «Сайты» → ваш домен → «Изменить»; затем раздел «PHP».**

Выберите PHP **8.2 или новее**. Убедитесь, что параметры применены именно к этому домену, особенно если включён отдельный `php.ini` для домена. [Настройки PHP в ispmanager](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/kak-smenit-versiyu-php-na-hostinge).

Для проекта нужны расширения: `pdo_mysql`, `mbstring`, `fileinfo`, `zlib`, `zip` и хотя бы одно из `gd` / `imagick` с поддержкой WebP. Желательно `exif` для ориентации фотографий.

Установите лимиты:

```ini
upload_max_filesize = 16M
post_max_size = 40M
memory_limit = 256M
display_errors = Off
log_errors = On
```

Это лимиты фотографий в админке, не архива сайта. В одной форме могут отправляться две фотографии до 15 МБ каждая.

В **«Базы данных»** проверьте версию MySQL. Для переноса используйте MySQL 8. Проект проверен локально на 8.4; это не заменяет проверку на сервере. REG.RU поддерживает MySQL 8 в ispmanager, но доступность зависит от услуги. Если доступна только 5.7, согласуйте переключение с поддержкой **до импорта**, особенно при наличии других сайтов. [MySQL 8 на REG.RU](https://help.reg.ru/support/hosting/bazy-dannykh/kak-pereyti-na-mysql8).

## 5. Загрузить файлы — важно не перепутать папки

**Где: «Сайты» → ваш домен → «Файлы сайта» / «Менеджер файлов».**

Корень сайта может выглядеть так:

```text
/var/www/ВАШ_ЛОГИН/data/www/ПАПКА_САЙТА
```

Возьмите реальный путь из панели. Имя папки может быть в кириллице или в Punycode; не переименовывайте её по примеру.

### 5.1. Публичная часть

1. Откройте **корневую директорию именно вашего домена**.
2. Если там только стандартная заглушка REG.RU, сохраните её вне корня сайта. Чужие файлы и существующий сайт не удаляйте наугад.
3. Нажмите «Загрузить», выберите **`site-public.zip`** на Mac.
4. После загрузки выделите архив → **«Извлечь»** в текущую папку.
5. В корне должны оказаться `index.php`, `.htaccess`, `api`, `assets`, `fonts`, `media`, `uploads`. Не должно быть лишней вложенности `public_html/public_html` или `site-public/index.php`.
6. Включите отображение скрытых файлов и проверьте наличие `.htaccess`, включая `uploads/.htaccess`.
7. После успешной распаковки уберите загруженный `site-public.zip` с сервера. Копия останется на Mac.

Менеджер файлов ispmanager поддерживает ZIP. Если загрузка большого архива не проходит, используйте SFTP по реквизитам вашей услуги либо попросите поддержку помочь с загрузкой. Не уменьшайте качество видео ради переноса. [Загрузка и распаковка файлов](https://help.reg.ru/support/hosting/razmeshcheniye-sayta-otobrazheniye-v-brauzere/kak-razmestit-sayt-v-ispmanager).

### 5.2. Приватная часть

1. Из корня сайта перейдите **ровно на один уровень выше** — обычно это `www`.
2. Убедитесь, что там нет папки `private` другого проекта. Если есть — остановитесь: объединять их нельзя.
3. Здесь загрузите **`site-private.zip`** и нажмите «Извлечь».
4. Появится папка `private` рядом с папкой домена.
5. После распаковки уберите архив с сервера; локальную копию сохраните.

Итоговая структура должна быть такой:

```text
www/
├── ПАПКА_САЙТА/          ← корень домена
│   ├── index.php
│   ├── .htaccess
│   ├── api/
│   ├── assets/
│   ├── fonts/
│   ├── media/
│   └── uploads/
└── private/             ← НЕ внутри корня домена
    ├── .htaccess
    ├── api/
    ├── database/
    ├── cron/
    ├── manifest.json
    └── config.example.php
```

Такое соседство обязательно для готовых PHP-загрузчиков. Не создавайте домен или псевдоним, который публикует папку `www` целиком либо `private`. Если панель не позволяет выйти из корня сайта, попросите поддержку разместить приватную часть вне публичного каталога.

## 6. Создать и импортировать базу

**Где: ispmanager → «Базы данных».**

1. Создайте **новую пустую базу** MySQL, например с коротким суффиксом `theatre`, и отдельного пользователя с доступом только к ней. Панель может добавить префикс к имени.
2. Выберите кодировку `utf8mb4`, сопоставление `utf8mb4_unicode_ci`.
3. Сохраните в менеджере паролей полное имя базы, имя пользователя, пароль и адрес сервера БД. Не путайте пароль БД с паролем админки сайта.
4. Выберите новую базу → откройте **phpMyAdmin**. Проверьте HTTPS без предупреждений.
5. В phpMyAdmin слева выберите эту базу → **«Импорт»** → файл **`database.sql.gz`** с Mac → формат SQL → «Выполнить».

**Не импортируйте дамп в базу другого или уже действующего сайта:** он содержит `DROP TABLE` и заменяет таблицы. Сам файл базы не загружайте через «Файлы сайта». [Работа в phpMyAdmin](https://help.reg.ru/support/hosting/bazy-dannykh/rabota-v-phpmyadmin).

После импорта во вкладке **«SQL»** выполните:

```sql
SELECT COUNT(*) AS performances FROM performances;
SELECT COUNT(*) AS events FROM events;
SELECT COUNT(*) AS faq FROM faq;
SHOW COLUMNS FROM events LIKE 'event_time';
DELETE FROM admin_tokens;
```

Для подготовленной копии ожидаются **22, 18, 5** и существующее поле `event_time`. Удаление `admin_tokens` завершает перенесённые локальные сессии, а не удаляет контент. Не запускайте `database/seed.php`: он предназначен для первичной установки, а не переноса заполненной базы.

## 7. Задать настройки сервера

**Где: «Менеджер файлов» → соседняя папка `private`.**

1. Сделайте копию `config.example.php` с именем **`config.php`**.
2. Откройте новый `config.php` для редактирования.
3. Заполните его по шаблону ниже, заменив все обозначения заглавными буквами:

```php
<?php
$config = require __DIR__ . '/api/config.example.php';
$config['environment'] = 'production';
$config['base_url'] = 'https://xn--80aanbjgaodo1bgudcs1l.xn--p1ai';
$config['db'] = [
    'dsn' => 'mysql:host=АДРЕС_БД;dbname=ПОЛНОЕ_ИМЯ_БАЗЫ;charset=utf8mb4',
    'user' => 'ПОЛНОЕ_ИМЯ_ПОЛЬЗОВАТЕЛЯ_БД',
    'password' => 'ПАРОЛЬ_БД',
];
$config['secrets'] = [
    'app' => 'ПЕРВЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ',
    'visitor_hash' => 'ВТОРОЙ_СЛУЧАЙНЫЙ_КЛЮЧ',
];
$config['uploads']['directory'] = '/var/www/ВАШ_ЛОГИН/data/www/ПАПКА_САЙТА/uploads';
$config['paths'] = [
    'logs' => __DIR__ . '/logs',
    'runtime' => __DIR__ . '/runtime',
    'backups' => __DIR__ . '/backups',
    'vite_manifest' => __DIR__ . '/manifest.json',
];
return $config;
```

Адрес MySQL берите из реквизитов БД, а не из адресной строки Safari. Если указан отдельный порт, добавьте в DSN `;port=НОМЕР` после `host=...`. Если адрес неизвестен, уточните его у поддержки. Путь `uploads` должен точно совпадать с фактическим корнем сайта из шага 3.

Одинарные кавычки или обратные слеши внутри значений PHP-строк требуют экранирования. Не публикуйте конфигурацию и не присылайте её с паролями в чат.

**На Mac**, в Терминале дважды выполните:

```sh
openssl rand -hex 32
openssl rand -hex 32
```

Два полученных разных значения вставьте в `app` и `visitor_hash`. Это секретные ключи, не пароль входа.

Внутри `private` создайте папки **`logs`**, **`runtime`**, **`backups`**. PHP должен иметь право записи в них и в публичную `uploads`. Обычно подходят 700/750 для приватных папок, 600/640 для `config.php`, 755 для публичных папок; точные права зависят от владельца процесса PHP. **Не ставьте 777.** При ошибке доступа попросите поддержку настроить владельца и разрешения.

Оставьте разрешённые origins админки из шаблона. Не заменяйте их на `*`. Никакие Node.js/npm-команды на сервере для сайта не нужны.

## 8. Заменить тестовый пароль админки до публикации

Старый локальный пароль нельзя оставлять на публичном сайте. Логин можно сохранить: **`alaving`**. Следующие действия меняют пароль только в новой серверной базе; локальная админка останется со своим прежним паролем.

1. Придумайте новый случайный пароль, лучше 20+ символов из менеджера паролей, и сохраните его там.
2. **На Mac в Терминале (zsh)** выполните первый блок и введите пароль по запросу:

```sh
cd /Users/artemalekseev/Desktop/theatrpesok
read -rs 'theatre_password?Новый пароль админки (16–72 байта): '
```

После ввода пароля и нажатия Enter выполните второй блок:

```sh
printf '\n'
printf '%s' "$theatre_password" | .local-tools/frankenphp php-cli scripts/hash-admin-password.php
unset theatre_password
```

Символы при вводе не отображаются. Пароль не нужно вставлять прямо в текст команды. Помощник напечатает хеш, начинающийся с `$2y$`; он сам **не меняет** никаких учётных записей. Если выведена ошибка, исправьте пароль и повторите.

3. В phpMyAdmin **новой серверной базы** откройте «SQL». Замените `ВСТАВЬТЕ_ХЕШ` всей полученной строкой, затем выполните:

```sql
UPDATE admin
SET password_hash = 'ВСТАВЬТЕ_ХЕШ', updated_at = UTC_TIMESTAMP()
WHERE login = 'alaving';
DELETE FROM admin_tokens;
```

Должна измениться одна учётная запись. Если ни одной — проверьте `SELECT id, login FROM admin;` и выбранную базу. Не вставляйте открытый пароль вместо хеша и не используйте MD5.

## 9. Проверить перенос, пока Tilda ещё работает

Сначала проверяем новый сервер, потом меняем направление домена. REG.RU допускает проверку через технологический домен или локальный `hosts`. [Проверка до изменения DNS](https://help.reg.ru/support/hosting/perenos-saytov/kak-proverit-korrektnost-perenosa-sayta-do-izmeneniya-dns).

Самый простой вариант: найдите технологический адрес в карточке услуги или запросите его у поддержки; он должен открывать **ту же корневую папку**, куда распакован сайт. Без этого адрес может показывать другую заглушку. На технологическом адресе канонические SEO-ссылки будут указывать на основной домен — это ожидаемо.

Если такого адреса нет, можно сделать предварительную **проверку публичного API без изменения DNS** из Терминала Mac:

```sh
curl --resolve 'xn--80aanbjgaodo1bgudcs1l.xn--p1ai:80:IP_ХОСТИНГА' 'http://xn--80aanbjgaodo1bgudcs1l.xn--p1ai/api/public/performances'
```

Вместо `IP_ХОСТИНГА` подставьте IP сайта из ispmanager, не IP из журнала входа. Ожидается JSON с `"success":true` и вашими спектаклями. Такая проверка не заменяет просмотр всех страниц и HTTPS. Не отправляйте по HTTP логин, пароль или заявки.

Для полноценной проверки в браузере используйте технологический домен с HTTPS либо настройте `hosts` по [инструкции REG.RU для Mac](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/fayl-hosts-gde-nakhoditsya-i-kak-yego-izmenit). Меняется только ваш компьютер. Не стирайте другие записи hosts; после проверки удалите только добавленную строку. Локальная подмена DNS сама по себе не создаёт сертификат. Предупреждения HTTPS не обходите.

До переключения проверьте:

- главную и видео, меню и возврат на главную;
- репертуар и страницу отдельного спектакля;
- афишу, дату и время начала, фотографии и ссылки на билеты;
- FAQ и франшизу;
- `/api/public/performances`, `/api/public/events`, `/api/public/faq`;
- неизвестный адрес, например `/missing-check`, возвращает 404;
- `/private/config.php`, `/config.php`, `/.env` и `/database.sql.gz` не открываются и не раскрывают содержимое.

Если код PHP предлагается скачать, это ошибка настройки PHP: не публикуйте сайт. Если видны секреты — закройте доступ и замените раскрытые значения.

## 10. Переключить домен с Tilda на REG.RU

**Где: сначала текущая DNS-панель, затем личный кабинет REG.RU.**

На ранее присланном скриншоте у домена были `ns1.tildadns.com` и `ns2.tildadns.com`. Проверьте, что сейчас это всё ещё так. Перед сменой сохраните список всех записей зоны: особенно MX и TXT для почты, SPF/DKIM/DMARC, а также используемые поддомены. Смена NS не переносит эти записи автоматически.

1. В ispmanager откройте **«Управление DNS»**, найдите или создайте зону вашего домена.
2. Проверьте A-записи основного домена и `www`: они должны вести на IP нового сайта. Не оставляйте параллельные записи для Tilda. AAAA добавляйте только при подтверждённой настройке IPv6 на новом хостинге.
3. Перенесите нужные почтовые записи и поддомены из старой зоны. Если в текущей зоне включён DNSSEC, сначала согласуйте обновление DS-записей с поддержкой: старые ключи могут сделать домен недоступным.
4. В личном кабинете REG.RU откройте **домен → «DNS-серверы и управление зоной» → «Изменить»**.
5. Для купленного виртуального хостинга REG.RU укажите:

```text
ns1.hosting.reg.ru
ns2.hosting.reg.ru
```

6. Сохраните. На время распространения DNS у разных посетителей могут открываться разные версии сайта. REG.RU указывает срок смены NS до 24 часов; мгновенное переключение не гарантируется. [DNS виртуального хостинга](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/obshchaya-informatsiya-o-dns-serverakh/v-chem-raznitsa-mezhdu-dns-serverami-ns1-reg-ru-ns2-reg-ru-i-ns1-hosting-reg-ru-ns2-hosting-reg-ru), [сроки обновления](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/onlayn-proverka-dns-zapisey-domena).

Не путайте их с `ns1.reg.ru` / `ns2.reg.ru`. После перехода на хостинговые NS записи редактируются в зоне хостинга. Сам проект Tilda пока оставьте: он пригодится для отката. Удалять его для отключения домена не нужно.

## 11. Выпустить и подключить HTTPS

**Важный момент:** обычный выпуск Let's Encrypt проверяет домен на новом сервере, поэтому до обновления DNS он может не пройти. Если сертификат ещё не готов, во время переключения возможны ошибки HTTPS. Для перехода без такого промежутка заранее согласуйте с поддержкой REG.RU выпуск сертификата через проверку DNS/TXT на действующих DNS-серверах. Это отдельная подготовка, а не гарантированный результат одной кнопки.

После того как домен направлен на новый хостинг:

1. В ispmanager откройте **«SSL-сертификаты» → «Добавить сертификат» → «Let's Encrypt»**.
2. Выберите ваш домен; добавляйте `www` только если он настроен. Wildcard для обычного сайта не нужен.
3. Выпустите сертификат и дождитесь успешного статуса. При ошибке смотрите журнал выпуска.
4. В **«Сайты» → ваш домен → «Изменить»** включите SSL, выберите выпущенный сертификат и сохраните.
5. Откройте `https://театрмузыкиипеска.рф` и убедитесь, что нет предупреждений.
6. Только после этого включите перенаправление HTTP → HTTPS.

Для запросов проверки сертификата в подготовленном `.htaccess` разрешён узкий путь `/.well-known/acme-challenge/`; остальные скрытые пути закрыты. Если выдача сертификата всё равно не проходит, проверьте DNS, CAA и журнал вместе с поддержкой; не отключайте защиту всего сайта. [Let's Encrypt в ispmanager](https://help.reg.ru/support/ssl-sertifikaty/3-etap-ustanovka-ssl-sertifikata/rasshireniye-let-encrypt-v-ispmanager).

## 12. Подключить приложение админки к настоящему сайту

**Где: Терминал на Mac.** Нынешняя админка обращается к `127.0.0.1:8080`, то есть к вашему компьютеру. После размещения сайта ей нужен новый адрес.

Сначала убедитесь, что по HTTPS работает:

```text

```

Закройте Theatre Admin через **⌘Q**. При желании сохраните копию прежнего приложения в отдельной папке как локальную версию. Затем выполните:

```sh
cd /Users/artemalekseev/Desktop/theatrpesok
export PATH="$PWD/.local-tools/cargo/bin:$PWD/.local-tools/node-v22.23.2-darwin-x64/bin:$PATH"
export RUSTUP_HOME="$PWD/.local-tools/rustup"

```

Дождитесь успешного окончания, не закрывайте Терминал посреди сборки. Она заменяет приложение по прежнему пути. Откройте:

```text
/Users/artemalekseev/Desktop/theatrpesok/admin/src-tauri/target/release/bundle/macos/Theatre Admin.app
```

Войдите под `alaving` и **новым серверным паролем из шага 8**. Должны отобразиться ваши спектакли и афиша. Сделайте небольшую проверочную правку существующей записи, сохраните и обновите страницу сайта; затем верните исходный текст.

После перехода работайте с этой серверной админкой. Изменения в старой локальной базе больше не синхронизируются с сайтом. Локальный тестовый сервер для реального сайта не нужен. В текущей неподписанной сборке вход хранится только до закрытия приложения; это ожидаемо, Связка ключей не используется.

## 13. Настроить ежедневную резервную копию

**Где: ispmanager → «Планировщик CRON» → «Создать задание».**

Если доступен тип «Выполнить PHP-скрипт», выберите серверный файл `private/cron/daily.php` и PHP 8.2+. Если доступны только команды, укажите:

```text
/ПОЛНЫЙ/ПУТЬ/К/php /var/www/ВАШ_ЛОГИН/data/www/private/cron/daily.php
```

Первый путь — к **CLI PHP**, не к `php-cgi`. Его нужно взять из настроек услуги или у поддержки. Не используйте произвольный системный PHP старой версии. [Настройка CRON на REG.RU](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/planirovshchik-cron).

Расписание: ежедневно, например 04:15 по часовому поясу сервера. Для полей cron: минуты `15`, часы `4`, остальные три поля `*`. В поле «Команда» само расписание не вставляйте.

Запустите вручную один раз и проверьте появление файла в `private/backups`. Скрипт сохраняет 7 дневных SQL-копий и 4 недельных ZIP-копии базы с фотографиями; недельный ZIP создаётся по воскресеньям. Видео и статические файлы сайта в эти копии не входят — сохраните исходный пакет отдельно. Периодически скачивайте резервные копии с сервера.

## Если что-то не работает

| Что видно | Что проверить |
| --- | --- |
| Старый сайт Tilda | NS/A/AAAA, кеш DNS; проверьте с телефона через мобильную сеть |
| Заглушка REG.RU | Тот ли корень сайта; нет ли лишней папки; распакован ли `index.php` |
| 500 / «Внутренняя ошибка сервера» | `private/logs`, PHP, расширения, реквизиты БД и права; не включайте показ ошибок посетителям |
| 503 / «Сайт временно недоступен» | Наличие `private/manifest.json` и файлов `assets` из той же сборки |
| Главная работает, внутренние страницы — нет | `.htaccess`, режим FastCGI (Apache), обработка rewrite |
| Нет фотографий | Публичная `uploads`, сохранённая вложенность, правильный абсолютный путь в config |
| Не принимается изображение | Лимиты PHP для домена, WebP в GD/Imagick, права на uploads |
| Админка не соединяется | Адрес сборки, HTTPS и сертификат; не используйте локальное приложение для сервера |
| Вход проходит, остальные запросы дают 401 | Передача заголовка Authorization из Apache/FastCGI в PHP; уточнить у поддержки, не отключать авторизацию |
| Неверный пароль | Правильная серверная база, логин `alaving`, именно PHP-хеш в `password_hash` |
| «Не удалось выпустить сертификат» | DNS уже указывает на новый сервер, верный IP/AAAA, журнал Let's Encrypt |
| Перестала работать почта | Перенесены ли MX/TXT и почтовые поддомены в новую DNS-зону |

Не исправляйте ошибки повторным импортом поверх работающего сайта: новые заявки и правки могут быть потеряны.

## Откат, если новый сайт не заработал

Сохранённый проект Tilda и прежняя DNS-зона позволят вернуть старое направление домена. Убедитесь, что Tilda ещё обслуживает ваш домен, затем верните прежние NS/записи из своей копии. Обратное обновление DNS тоже занимает время.

Новую базу и uploads не удаляйте: там могли появиться заявки и изменения. Перед любым восстановлением сделайте их копию. Не запускайте импорт исходного дампа в действующую базу без учёта новых данных.
